## 方針

ユーザー確認済みの4項目:

1. ボット対応。
2. ジャンル詳細を集約データへ対応させる。
3. 販売履歴の保存を `metricYears` に統一し、`dailyMetrics` への二重書き込みを終了する。
4. 発売初日の日別販売本数を、翌日の実取得時点の累計販売本数で確定する。

4項目を合わせた再確認結果は[統合レビュー](four-change-integrity-review-2026-09-12.md)を参照。ユーザー指定により、通常日は再実行しない前提とし、そのための差分再計算・元の基準累計の追加保持・復元処理は対象外にする。4は発売初日の確定に限定し、以降の日次差分は現行仕様を維持する。実装・本番反映は未実施。

3は販売履歴の書き込み方式の変更を指す。通常の商品情報 `products` の更新は続ける。検索の旧索引生成停止や、ジャンル画面の従来取得への切り戻し廃止は含まない。

採用条件は、既存機能・表示・性能を維持し、Readと総費用を減らし、大きなデメリットや既知のデグレを残さず、対象ボットの巡回を一定程度抑えること。Read削減だけで性能・総費用の条件を満たしたとは判定しない。

この一覧は、先行調査の「ジャンルは段階取得を検討」「フッター先行」から更新した実装対象をまとめる。ジャンル詳細は専用の集約データと更新連動の利用制御を設計する。以前に不適合とした、既存の日次compact索引をそのまま読むだけの方式は採用しない。

Web、Cloud Run Job、Functions、設定の反映単位を分ける。ジャンル取得は専用切替、robotsは対象ルール、履歴は保存形式と期間補完の手順で戻す。ロールバックできることと、無条件・即時に戻せることを混同しない。
